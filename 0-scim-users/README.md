# 3-scim-users — SCIM user & user-group replication

Replicates **all users and user groups** from the `<source-profile>` tenant (account
`<account-id>`) into a committed CSV dataset, and pushes that dataset into a target
tenant through the **custom SCIM connector** using `catocli scim` bulk commands.

By default the export sources from the **user query** (`user.userList` /
`user.usersGroupList`), so it captures EVERY user/group regardless of
importType (MANUAL, SCIM, LDAP, INTEGRATION) — full coverage, not just
SCIM-provisioned ones. `--import-type manual|scim|…|all` narrows it (default
`all` — keep all so group members, which can differ in importType from the
group, still resolve). `--source scim` restores the legacy SCIM-connector-only
capture. Objects the query returns without an external_id (e.g. MANUAL users)
get a synthesized `q:<email>` / `q:<name>` key. **Caveat:** every pushed user
lands as **SCIM** importType in the target, even originally-MANUAL ones —
expected for a replica.

**This folder is catocli-only — there is no Terraform here.** Users and user
groups are not managed by any provider resource in this repo; the SCIM API
(via catocli) is the system of record for them. The `3-` prefix places this
after every Terraform phase in the replication order: policies can reference
users/groups, but pushing users requires no Terraform state at all.

## Layout

This folder holds docs only — per repo convention, **all catocli export data
lives in the shared root `config_data/`**:

```
config_data/
├── scim_users.csv       committed dataset (generated by scim_sync.py export)
├── scim_groups.csv
└── scim_raw/<profile>/  raw un-normalized captures per tenant (gitignored,
                         written by export/purge runs — never system temp)
```

## CSV schema (catocli scim import contract)

`scim_users.csv` — `email,given_name,family_name,external_id,password,active,user_id`

- `user_id` is deliberately **blank** in this dataset: on `scim import`, a
  missing id means **CREATE** (present would mean UPDATE). The export
  normalizer blanks it so the dataset replays cleanly into an empty tenant.
- `password` never round-trips from export (the SCIM API doesn't return
  secrets); the column exists for the import contract. Leave blank unless
  deliberately seeding initial passwords.
- `external_id` is the **cross-tenant join key** — never edit it by hand.

`scim_groups.csv` — `group_id,display_name,external_id,member_external_ids`

- `member_external_ids` is pipe-separated (`john.doe|jane.smith`) and
  references `external_id` values from `scim_users.csv`. The push dry-run
  cross-checks every member against the users file.
- `group_id` blank, same CREATE semantics as `user_id`.

## Prerequisites

Both profiles need SCIM connector credentials (the `scim_url` embeds the
account id and SCIM source id):

```bash
catocli configure set --profile <name> --scim-url <url> --scim-token <token>
python3 scripts/cato_profile.py <name>    # shows "scim: configured"
```

Already configured for: `<source-profile>` (source) and `<target-profile>` (target).

## Workflow

```bash
# 1. Refresh the dataset from the source tenant (READ-ONLY)
python3 scripts/scim_sync.py export --source-profile <source-profile>

# 2. Review the git diff of config_data/scim_*.csv — rows are sorted for stable diffs

# 3. Dry-run the push (local schema + membership checks, no API calls)
python3 scripts/scim_sync.py push --target-profile <target-profile>

# 4. Real push (interactive: type the target account id to confirm) -- use a
#    non-production target profile first
python3 scripts/scim_sync.py push --target-profile <target-profile> --execute

# 5. Promote to the real target once the test push above looks right
python3 scripts/scim_sync.py push --target-profile <target-profile> --execute
```

To clear a target tenant's SCIM objects first (e.g. before a clean
replication rehearsal):

```bash
python3 scripts/scim_sync.py purge --target-profile <target-profile>            # dry-run inventory
python3 scripts/scim_sync.py purge --target-profile <target-profile> --execute  # groups, then users
```

## Safety model

- `export` only ever reads, and only from `--source-profile`.
- `push`/`purge` **refuse the source tenant**: profiles named
  `<source-profile>` (or its read-only variant) or any profile resolving to account
  `<account-id>`. There is no override flag.
- `push`/`purge` default to dry-run; `--execute` additionally requires an
  interactive typed confirmation of the resolved account id.
- Always test against a non-production target profile before the real target
  profile.

## Verifying a push

```bash
CATO_PROFILE=<target-profile> catocli scim get_users -p
CATO_PROFILE=<target-profile> catocli scim get_groups -p
# or compare counts against the dataset:
wc -l config_data/scim_*.csv
```

## Troubleshooting

- `profile ... has no scim_url/scim_token configured` — run the
  `catocli configure set` command above for that profile.
- `member ... not present in scim_users.csv` — the group references a user
  the export didn't capture (e.g. a non-SCIM user added to a SCIM group in
  CMA). Either add the user upstream and re-export, or remove the member.
- Import says UPDATE instead of CREATE — the CSV has ids populated; re-run
  the export (the normalizer blanks them) rather than hand-editing.
- `scim import` partial failures: re-running is safe — rows that already
  exist resolve by `external_id` and update in place.
